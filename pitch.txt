"I built a question-answering system for financial reports — the problem is that retail investors make decisions on companies without reading their filings, because a 10-K is a hundred-plus pages of dense accounting language. My system takes any SEC filing, and you ask questions in plain English. It's a RAG pipeline — chunking, embeddings in ChromaDB, reranking, LLM generation — deployed on Streamlit Cloud.
What I'm most proud of is the evaluation. I tested it on a 21-question subset of FinanceBench across four real 10-Ks, with an LLM judge deliberately separate from the generator, and ran an ablation over chunk size and reranking. Best configuration hit 70% accuracy, and abstention was near-perfect — when the answer wasn't in the document, it said so instead of hallucinating a number, which for financial data matters more than raw accuracy. The most interesting finding was that reranking actually hurt performance at larger chunk sizes — my hypothesis is the cross-encoder favors narrative text discussing the question's terms over the financial tables containing the actual numbers.
The evaluation also broke twice before it worked: Ollama was silently truncating my prompts at its default context window, which I caught from the token counts in the API response, and my judge model was scoring correct 'I couldn't find that' answers as failures, which I fixed by routing abstention questions to a separate rubric in code instead of trusting the judge to apply a conditional. So the numbers I report are ones I actually trust."
